# Localization (i18n)

Comicarr's web UI is translatable. English is the source language; every other
language is a gettext catalog that translators fill in. This page is the
contract for contributors writing UI code.

## The pieces

| Piece | Where | Job |
|---|---|---|
| Lingui | `@lingui/core`, `@lingui/react` | Runtime: looks up a message in the active catalog, handles plurals and placeholders (ICU MessageFormat). |
| Macros | `@lingui/react/macro`, `@lingui/core/macro` | Authoring: `t`, `<Trans>`, `msg`, `plural`. Expanded at build time by `@lingui/vite-plugin` with `macroTransform: true`, so there is no Babel pass. |
| Catalogs | `frontend/src/locales/<locale>/messages.po` | One gettext file per language. `en` is generated from the source; the others come from translators. |
| Runtime seam | `frontend/src/lib/i18n.ts` | Detects and activates the language, lists available ones. |
| Format seam | `frontend/src/lib/intl.ts` | Every date, time, number, size and relative time. |
| Gate | `frontend/scripts/check-i18n.mjs` (in `npm run lint`) | Catalog in sync with the source; unlocalized text only shrinks. |

## Writing a string

Inside a component, use the macros:

```tsx
import { Trans, useLingui } from "@lingui/react/macro";

function Example({ count }: { count: number }) {
  const { t } = useLingui();
  return (
    <>
      <h2><Trans>Wanted</Trans></h2>
      <input placeholder={t`Search or add`} />
      <p><Trans>{count} need you</Trans></p>
    </>
  );
}
```

At module scope there is no active language yet, so define a descriptor with
`msg` and translate it when rendering:

```tsx
import { msg } from "@lingui/core/macro";
const OPTIONS = [{ value: "light", label: msg`Light` }];
// in the component: i18n._(option.label)
```

Rules that keep strings translatable:

- **One sentence, one message.** Never build a sentence from pieces
  (`"Out " + weekday`, `` `${verb} ${n} of ${m}` ``). Word order differs between
  languages; put the whole sentence in one message with placeholders.
- **Plurals go through `plural`**, never `n === 1 ? "issue" : "issues"`:
  `` t`${plural(n, { one: "# issue", other: "# issues" })}` ``. Many languages
  have more than two forms.
- **Numbers inside a message are formatted by the message**, not by
  `formatNumber` first.
- **Don't translate data.** Series titles, publishers, file names, usernames and
  log lines stay as they are.
- **Add context when a word is ambiguous**: `` t({ message: "Issue", context: "comic issue, not a problem" }) ``.

## Dates and numbers

`src/lib/intl.ts` is the only place that builds `Intl` formatters. Use
`formatDate`, `formatNumber`, `formatBytes`, `formatRelative` and
`formatCompactSince`. They use the browser's regional variant of the active
language (UI English + browser `en-GB` gives day-first dates), never a
different language from the text, and they cache formatters.
ESLint rejects a hardcoded `"en-US"`, `toLocaleString()` and friends, and
`new Intl.*` anywhere else.

## The backend

The UI owns the words. An API response that the UI shows should carry a code
and parameters (`reason_code`, `count`, `series`), not an English sentence.
Activity rows already work this way. Backend text that still reaches the UI as
prose is being moved to codes; log lines, MCP tool descriptions and push
notifications stay English.

## Which language a user sees

1. The language picked in the account menu, saved in this browser.
2. Otherwise the browser's languages, matched exactly, then by base language
   (`de-AT` uses `de`), then by region (`pt` uses `pt-BR`).
3. Otherwise English.

The choice is per browser, not a server setting, so two people sharing one
install can each read it in their own language. The picker appears once a
second catalog exists.

## Adding a language

Create `frontend/src/locales/<locale>/messages.po` (or let the translation
platform do it) and run `npm run i18n:update` in `frontend/`. Both the Lingui
config and the app discover languages from that folder, so no code changes.
Inter Tight is bundled with Latin and Latin Extended subsets only; a language in
another script also needs its font subsets added in `src/main.tsx`.

## The gate

`npm run lint` in `frontend/` runs `scripts/check-i18n.mjs`, which fails when:

- a catalog is out of date with the source (`lingui check sync`), or
- a file has more unlocalized text than `i18n-baseline.json` allows, or fewer
  (the baseline must be lowered with it, so it never hides new debt).

Fix the code, then run `npm run i18n:update`: it re-extracts the catalogs and
lowers the baseline. It never raises a count. `eslint.i18n.config.js` decides
what counts as user-facing text. If it flags something that is not, such as a
query key, add the name or function to its ignore lists rather than adding a
baseline entry.

Contributor-only gate: no changeset.
